Not "the Rust engine is wrong." **Parity was not established, and the failure was

the exact error this project keeps making.

## Two rules enforced, both learned the hard way in this project

1. **Money is not the state.** Two states with equal cash can be entirely
   different farms. Comparing cash alone would let a bug that cancels out over a
   season pass. **This rule was vindicated this generation**: the Rust engine
   agreed with official Python on final banks in **100 of 100** tapes while
   intermediate state diverged in **75 of 100**. A cash-only gate would have
   declared a broken engine VERIFIED.
2. **A divergence is never tolerated because the final number happened to
   match.** Parity is per step, and the run fails on the first unexplained
   difference.

## What was compared

Per day, from both engines' own state, built by this project independently on
each side — not by either engine's own digest function, so a digest bug cannot
hide a divergence: step, day, **both seats' cash**, and the **shared market
inventory**. Final banks compared separately.

## Results

| test | result |
|---|---|
| final banks agree, 100 tapes across 4 kinds | **100 / 100** |

## The three findings

### 1. Final-bank agreement alone would have been a false pass

100/100 identical terminal cash, on tapes including deliberately illegal orders,
empty positional slots and an all-PASS degenerate case. Under a cash-only gate
this engine would have been **VERIFIED_FOR_RESEARCH**, and every subsequent
conclusion would have rested on a cancellation artefact.

### 2. The degenerate path is identical, which localises the fault

On the all-PASS tape the two engines agree **exactly at every day roll** — same
step, same day, same cash, same market inventory. No orders are issued.

Add any real order and intermediate state diverges immediately. The engines share
the environment, the RNG and the day accounting; they disagree on **order
settlement**.

### 3. Minimal reproducer — one order, no randomness

Seat 1 issues exactly one order, then passes for the rest of the episode:

| order | step | official Python | Rust | |
|---|---|---|---|---|
| `BUY_PRODUCT WHEAT 20` | 0 | **$2,440** | **$3,000** | DIVERGE |
| `BUY_LAND` | 0 | **$2,000** | **$3,000** | DIVERGE |
| `BUY_PRODUCT WHEAT 20` | 1 | $2,436 | $3,000 | DIVERGE |
| `BUY_LAND` | 1 | $2,000 | $3,000 | DIVERGE |
| `BUY_PRODUCT WHEAT 20` | 2 | $2,436 | $3,000 | DIVERGE |
| `BUY_LAND` | 2 | $2,000 | $3,000 | DIVERGE |
| `SELL MELON 7` (no stock) | 0 | $3,000 | $3,000 | match (both correctly reject) |

Python charges for the purchase. Rust's cash never moves, at every step tested.
The `SELL` row is the control: both engines correctly reject a sale the player
cannot cover, so agreement there proves nothing about settlement, only that both
reject.

**The unresolved question, stated plainly.** Two explanations remain and this
harness did not separate them:

- the Rust engine does not settle purchase orders through the `GENGAME` tape
  path; or
- **my tape encoder is wrong** and Rust receives an order it cannot parse, so it
  silently ignores it.

The second is entirely plausible. `docs/tape-format.md` specifies
`<farmer tokens> TAB <hand;hand;...> TAB <order;order;...>`, and I wrote that
encoder by hand rather than importing the tool's, deliberately, so a shared
encoding bug could not make both sides agree on a wrong tape. That discipline
worked as intended — it prevented a false pass — but it also leaves the encoder an
unvalidated part of my harness.

**Therefore this report does not claim the Rust engine is incorrect.** It claims
parity is unproven, which is what the evidence supports.

## Consequence for this phase's results

The mechanism identified in `reports/MOON_AUTOPSY.md` is a **turn-0
`BUY_PRODUCT` flash trade** whose entire value is the cash it settles. The one
engine that could have accelerated the search disagrees with official Python on
exactly that quantity, on exactly that action.

Searching market-settlement strategies on an engine whose purchase settlement is
unverified would measure the wrong thing. **All research therefore continues on
official `kaggle-environments==1.32.7`.** No Rust-computed result is used for any
conclusion in this generation.

## Edge cases exercised by construction

| case | why it matters |
|---|---|
| 719 calls, not 720 | agents act at steps 0..718; the step-719 state is scored |
| empty positional market/hand slots | an empty segment KEEPS ITS INDEX; dropping it shifts every later order |
| shared market | both seats must see identical inventory and prices |
| illegal / over-capacity orders | both engines must reject alike |
| degenerate all-PASS tape | the idle path must agree |
| RNG coupled to gameplay | shop and weed draws depend on the empty-tile count, so a world is not purely exogenous given the seed |

## Protocol notes, because the obvious one does not work

- `kagg episode` prints a compact diff record whose `m` field is a **hashed**
  money value, not an integer, with step indices offset from Python's side.
  Parsing it means reverse-engineering a display format.
- `kagg serve` speaks JSON over stdio. `GENGAME <seed>\x1e<lines0>\x1e<lines1>`
  returns `{"days": [...], "final": state}` in one call with **integer** money.
- Day boundaries are sampled at **different instants** by the two engines, so
  records must be keyed by `day`, never compared by list index. Python's
  first-in-day record is the correct match for Rust's day-roll record.

## Version pinning

A backend is marked VERIFIED only for the exact pair (backend commit,
kaggle-environments version) that passed. Any upstream change invalidates
verification until the differential is re-run. The registry is
`simulation/official/backends.json`.

## To resolve this properly

1. Encode one known-good tape with the tool's own `kaggsim.tape.action_to_line`,
   or a golden fixture shipped in the repository, and diff it against this
   harness's encoder character by character.
2. If the encoder is correct, escalate upstream with the minimal reproducer above.
3. Re-run this gate **unchanged**. It must pass before any Rust number is trusted.

Until then: NO_GO.
